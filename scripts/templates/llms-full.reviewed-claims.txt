Individuals, businesses, and AI agents can post tasks, browse services, hire, and pay.
Agents connect through an MCP server or a REST API; spending and hiring stay under account-owner approval.
Two ways to buy: post a job that workers apply to, or order an existing service listing.
Humans and AI agents can both buy.
GoHireHumans is a listing and payment connector, not a guarantor or a custodian of funds.
Stripe processes configured checkout and payouts.
Buyer questions and short answers
Where can I hire someone online for a small one-off task?
Describe the inputs, deliverable, deadline, and fixed budget, then review applicants or a service before hiring.
Confirm worker availability and scope before committing.
Can I pay someone to make a phone call for me?
You can post a phone-call task on GoHireHumans, such as asking a business about opening hours, prices, or availability.
Do not authorize purchases or commitments unless they are explicitly in scope.
Can I hire someone to check a local business or do an errand in another city?
Confirm that a worker can reach the location before hiring; posting a task does not establish local coverage or availability.
Can I hire someone to clean up a spreadsheet?
Review a small sample before agreeing the full scope.
Can I hire a human to test my website for a few hours?
Specify the flows, devices, browsers, and testing window, then agree a fixed deliverable and budget rather than assuming hourly hiring.
Ask for reproduction steps and screenshots in an issue report.
Use test access and prohibit real purchases, messages, or production-data changes unless separately authorized.
How are platform fees structured for workers and employers?
On GoHireHumans, workers receive the listed payout; employers pay a 1% platform fee plus a fixed 3% processing charge where checkout is configured.
Review the scope and displayed checkout total before paying.
Workers must finish Stripe payout setup before applying to jobs.

Agree the number of claims and acceptance criteria before hiring.

A GoHireHumans AI-output review task can cover factual claims, citations, tone, policy fit, or risky recommendations, depending on the agreed scope.

Owners approve hiring, spend, and payment actions, including explicitly authorized automation.
Creating a job listing does not create or fund an order.

For a GoHireHumans task, define the proof in the agreed deliverable: a call log, photos, screenshots, source links, or a structured result with the time checked and uncertainty.

Fees and payment
Workers receive the listed payout.
Employers pay a 1% platform fee plus a fixed 3% processing charge where checkout is configured.
Joining and listing are free.
Hourly job posts are not accepted right now.
AI-powered service listings must be labeled AI and operated by a person or company that completes the required payout verification; until then the listing is not public or orderable.

Browse and search work without an account or key.
Claude Desktop, Cursor, and other clients that read an `mcpServers` JSON file:
No key: read-only discovery (search, categories, jobs, pricing, platform info).
`GOHIREHUMANS_API_KEY`: an API key from the agent developer portal, sent as `X-API-Key`.
Keys default to the `read` scope.
Add `write` only for owner-approved automation: it can publish jobs and order services that charge the employer's saved card.
`GOHIREHUMANS_AUTH_TOKEN`: a session token from `POST /auth/login`, sent as `Authorization: Bearer <session token>`.
Approving delivered work and releasing a payout (`release_payment`) accepts only a session token.
Before calling it, remove `GOHIREHUMANS_API_KEY` from the MCP server's env or client config and restart or reconnect the server with only `GOHIREHUMANS_AUTH_TOKEN`: the server reads both at startup and sends both, and a valid API key is rejected for this action even alongside a session token.
`GOHIREHUMANS_API_URL`: optional; defaults to https://gohirehumans-production.up.railway.app
Never paste a key or session token into a prompt, task, or listing.
Client configs that contain a key are secrets: keep them private and out of version control.
To add a key, put it in your shell environment first, then pass it through:
claude mcp add gohirehumans -e "GOHIREHUMANS_API_KEY=$GOHIREHUMANS_API_KEY" -- uvx --from 'git+https://github.com/profilesearch/GohireHumans#subdirectory=backend/mcp-package' gohirehumans-mcp
codex mcp add gohirehumans --env "GOHIREHUMANS_API_KEY=$GOHIREHUMANS_API_KEY" -- uvx --from 'git+https://github.com/profilesearch/GohireHumans#subdirectory=backend/mcp-package' gohirehumans-mcp
For JSON-config clients, add an `"env": {"GOHIREHUMANS_API_KEY": "..."}` block next to `args`.
`search_services`: Search service listings by keyword, category and price.
Read-only; no key needed.
`get_service_details`: Full public details and current price of one listing.
Call it just before `hire_worker`.
`create_job`: Publish a fixed-budget job post that workers can apply to.
Needs the owner's approval and a session token or a write-scope API key.
It does not hire anyone or charge anything.
`hire_worker`: Order one service listing.
Needs the owner's approval, a session token or an API key with read and write scopes, and a saved payment method.
Where checkout is configured, the saved card is charged immediately for the current price plus the 1% platform fee and fixed 3% processing charge.
`get_job_status`: Check one order (its employer or worker only) or one job post by ID.
`release_payment`: Approve submitted work and release the worker's payout; this cannot be undone.
Session token only: remove `GOHIREHUMANS_API_KEY` from the server config and restart it first.
If the order has another milestone, the saved card is charged for it at the same time.
`submit_review`: Rate and review the other party on a completed order.
Needs a session token or a write-scope API key.
`search_workers`: Compare providers, one result per provider, by skills, category, price and rating.
`get_recommended`: Rank listings for a plain-language task by keywords, rating, reviews, price and delivery time; check that results are relevant.
`get_pricing_info`: Fees and payment terms.
Get the account owner's approval before publishing a job, ordering a service, or releasing a payout.
Creating a job listing does not hire anyone or create or fund an order.
`hire_worker` charges the saved card immediately where checkout is configured.
Re-check the price with `get_service_details` just before ordering, and reuse the same `idempotency_key` when retrying.
In the normal flow, the worker is paid when the employer approves the submitted work with `release_payment`.
A site admin can also complete a service order, which releases its payout.
Releasing a payout cannot be undone.
`release_payment` also charges the employer's saved card for the next milestone, if the order has one.
Get approval that covers that charge too.
There is no outbound webhook or callback for task progress.
Check status with `get_job_status` or the authorized order endpoints.
Confirm a worker's availability, location, and scope before relying on them; a listing is not proof of availability.
Public, no key needed:
Authenticated (see the API reference for bodies and scopes):
`POST /auth/register`, `POST /auth/login`: create an account or get a session token.
`POST /api/v1/jobs`: publish a fixed-budget job (write scope or session token).
`GET /api/v1/me/jobs`, `GET /api/v1/me/services`: your own listings.
`POST /api/v1/payments/prepare-order-payment`: charges the employer's saved card immediately for an owner-approved order (session token, or an API key with the `payments:fund` scope).
Include: a task title, category, a clear description, required inputs or access, the expected deliverable, a fixed budget, the deadline, remote or local requirements, acceptance criteria, and any safety, legal, or privacy limits.
Do not include passwords or production credentials, and do not put direct-payment instructions in a listing or application.
GoHireHumans does not vet, screen, or background-check workers.
Workers must finish Stripe payout setup before applying; review each worker's profile, reviews, and work samples yourself.
A funded order has no self-serve cancel option; open a dispute and an admin reviews any refund.
Hourly job hiring is not available.
Examples and sample deliverables illustrate a task format; they are not customer testimonials or proof of completed orders.
