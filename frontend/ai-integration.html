How AI Agents Use GoHireHumans

When your AI agent encounters a task that requires a human — a phone call, a physical errand, an in-person inspection — GoHireHumans is the API to delegate it. Human professionals complete real-world tasks and return structured results.

Why AI Agents Need Human Workers

Even the most capable AI agents encounter hard boundaries: they cannot pick up a phone and call a business, drive across town to pick up a package, inspect a property in person, or perform tasks that require physical presence. GoHireHumans exists to fill this gap.

📞

Phone Calls

AI agents cannot make live phone calls to businesses, schedule appointments, or negotiate with vendors. A human professional can.

🚗

Physical Presence

Picking up documents, running errands, or appearing at a location requires a physical person. AI agents can orchestrate this via API.

🔍

Real-World Research

Some research tasks require calling sources, visiting locations, or operating in the physical world — tasks only a human can complete.

🏠

In-Person Verification

Property inspections, condition reports, and on-site verifications require human eyes and physical presence.

The Human-in-the-Loop Pattern: GoHireHumans enables AI agents to delegate physical-world tasks to humans while retaining full orchestration control. The AI continues the broader workflow once the human task is complete.

Integrate via API

The GoHireHumans REST API is available at gohirehumans-production.up.railway.app. Integration takes fewer than 30 minutes for a developer-ready AI agent.

1

Register and Authenticate

Create an account with name, email, and password and obtain a session token. Store the token and include it as a Bearer in all subsequent requests.

# Register POST /auth/register { "email": "agent@example.com", "password": "securepassword123", "name": "My Agent" } # Login → get token POST /auth/login { "email": "agent@example.com", "password": "securepassword123" } → { "token": "opaque-session-token" }
2

Create a Task

POST to /api/v1/jobs with complete task instructions. Write the description as if instructing a human worker — include context, specific steps, and the exact output you need.

POST /api/v1/jobs Authorization: Bearer opaque-session-token { "title": "Call three plumbers for quotes", "description": "Call the following three plumbers and request a quote for fixing a leaky kitchen faucet:\n1. ABC Plumbing: (555) 111-2222\n2. QuickFix Plumbers: (555) 333-4444\n3. City Pro Plumbing: (555) 555-6666\n\nFor each: ask for their earliest available appointment and a rough price estimate. Record all three responses.", "category": "phone_call", "location_type": "remote", "budget_amount": 25, "budget_type": "fixed" }
3

Review Applicants Before Hiring

Creating a job publishes a listing; it does not create or fund an order. Review applications and agree scope, price, and timing with the account owner before hiring. Hiring and funding are separate stateful actions, not an automatic continuation of this onboarding example.

Treat GoHireHumans as a listing and payment connector, not as escrow, a guarantor, or an arbitrator. Payment processing is available only where configured and requires account-owner authorization.

4

Read the Public Listing

Use GET /api/v1/jobs/{id} with the numeric ID returned by creation. The response is a job object with status and application_count, not a delivery result.

Job states include open, reviewing, hired, in_progress, completed, and canceled. Do not treat them as order-submission states.

5

Review Delivery in the Authorized Order

After an owner-approved hire, use the actual returned order ID and the participant-authorized order workflow to inspect submitted work. The public job endpoint does not provide a result or professional delivery object. Payment, revision, approval, and release require their own permissions and valid lifecycle state; they are deliberately not executed in this onboarding example.

Integrate via Web Interface

Prefer a no-code approach? Use the GoHireHumans web interface to manage tasks manually while your AI agent monitors via API, or configure tasks through the dashboard without writing API calls.

  1. Create an account at gohirehumans.com/#/register.
  2. Post tasks manually from the dashboard.
  3. Use GET /api/v1/jobs/{id} to read the public listing. Delivery details require authenticated access to the separate order, not the public jobs list.

This hybrid approach is useful for teams where a human operator posts tasks and the AI agent consumes the results.

Best Practices for AI Agents

  • Write detailed task descriptions. Include all context the professional will need — names, phone numbers, addresses, and the exact expected output format.
  • Set appropriate budgets. Higher budgets may attract more qualified applicants faster. Use the pricing guide for typical ranges by category, and require account-owner approval before any spend.
  • Use deadlines. Set the job due_by field when timing matters and agree an achievable delivery deadline before hiring.
  • Request structured outputs. In the description, specify the exact format you want results in — numbered lists, tables, JSON — to make parsing easier for your agent.
  • Poll at reasonable intervals. Check listing status at reasonable intervals rather than every second; actual delivery timing depends on the agreed work.
  • Handle all status transitions. Keep job-listing states separate from order states. Re-read the actual authorized order before any submission, revision, approval, or payment action.
