# Public shell design-system contract

The public shell is the navigation and footer every public page shares, plus the page-level baseline that makes those pages consistent and accessible. Visual tokens, components, and page patterns live in [`design-system.md`](design-system.md); this file covers the shell and its executable contract.

Canonical public shell components live in `frontend/partials/`:

- `public-nav.html` — the `<div class="lp-nav-wrap">` block: the masthead strip (`.lp-masthead`, first child), the `<nav class="lp-nav">` bar with the serif wordmark `<a class="lp-nav-logo" href="/">GoHireHumans<span class="lp-nav-logo-dot" aria-hidden="true">.</span></a>`, and the mobile menu
- `public-footer.html` — the `<footer class="lp-footer">` block (same wordmark pattern with `lp-footer-logo-dot`)

## Baseline for every public HTML page under `frontend/`

Every page (recursive, excluding `partials/`, `node_modules/`, `test-results/`, and `playwright-report/`) must carry:

1. Exactly one `<div class="lp-nav-wrap">`, synced byte-for-byte from the partial. The only allowed per-page difference is the active link (`lp-nav-link-active` / `aria-current="page"`).
2. Exactly one `<footer class="lp-footer"`, synced from the partial. One footer per page; no legacy `<footer class="site-footer"`, `<footer class="footer"`, `<footer class="ftr"`, `<div class="footer">`, or `<header class="header">` shells.
3. A skip link `<a class="skip-link" href="#main-content">` as the first focusable element and a `<main id="main-content"` landmark.
4. `<script src="/analytics-bootstrap.js"></script>` as the only analytics entry point (no direct gtag/GTM tags).
5. Exactly one `<meta name="theme-color">` (paper `#f4efe6`).
6. No builder or generator attribution (`Perplexity`, `perplexity.ai`, `Created with`, `Generated by`) and no empty `href=""`.

`index.html` (the SPA) renders its nav and footer from JavaScript templates that must mirror the partials by hand; the guard skips only the two exactly-once shell checks for it. Its signed-in app surfaces are styled by `app.css`, which only `index.html` loads; static pages never load `app.css`.

Internal working documents (content plans, SEO status, Search Console notes, the analytics dashboard) live in `docs/ops/`, not under `frontend/`, so everything deployed is a public page held to this baseline. `robots.txt` also disallows `/internal/`.

## Shell rules

1. Public pages use the shared `lp-nav` navigation language.
2. Desktop navigation is marketplace-first: `Marketplace`, `Find Work`, `For Agents`, `Pricing`, `Trust`.
3. Account and transaction controls remain separate: `Sign in` and the primary buyer action `Post a task`.
4. Starter offers, use cases, and FAQ remain secondary resources in the mobile menu and/or footer rather than competing desktop tabs.
5. Footer text and links use readable text tokens, not low-contrast inline rgba values.
6. Navigation pages include `style.css?v=20260526-nav-consistency` (the query string is pinned by tests; CSS and JS are served with `max-age=0, must-revalidate`, so it does not need to change per release); public nav hover and active states must not inherit page-local `a:hover` rules. The active link is marked by a 2px red rule (`::after`), never by a background tint.
7. Pages must not mix canonical `lp-footer` markup with old local `.footer` shells.
8. The mobile footer is intentionally compact: broad marketplace, company, and legal routes only (at most 13 links, no taller than 700px at 393px wide); `Find Work` is the canonical worker label.
9. Public pages avoid visible builder/generator attribution and generic CTAs such as `Get started` when a specific action exists.
10. Use-case pages remain grouped under `Marketplace`; starter QA remains an optional wedge, not the platform-wide identity.
11. The wordmark's red period is decorative and must stay `aria-hidden="true"` so the accessible name of the logo link is exactly `GoHireHumans`; the nav-label regression helper ignores aria-hidden spans for the same reason. Never add `aria-label` to `.lp-nav-logo`.
12. The footer tagline carries the pricing framing verbatim: workers receive the listed payout; employers pay Stripe processing plus a 1% GoHireHumans fee where checkout is configured. Nothing in the shell describes GoHireHumans as escrow, a guarantor, or an arbitrator, or claims universal worker verification.

## Executable contracts

Run all three after changing the shell or adding a page:

```bash
python3 scripts/sync_public_shell.py --check   # byte-exact nav/footer sync; run without --check to propagate the partials
python3 scripts/check_public_shell.py          # partial tokens plus the per-page baseline above
python3 -m unittest backend.test_deep_audit_regressions.FrontendStaticRegressionTests
```

`check_public_shell.py` checks every public page, prints each offending file with its problems and a count per problem type, and exits non-zero on any drift. A new page must also be added to `frontend/sitemap.xml` with a matching extensionless redirect in `frontend/vercel.json`, and the pinned `analytics-bootstrap.js` page count in `backend/test_deep_audit_regressions.py` must be updated.

Regression coverage is in `backend/test_deep_audit_regressions.py` and `frontend/tests/browser-regression.spec.js`.
